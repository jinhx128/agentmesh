# Studio 写操作统一 Toast 设计

## 目标

统一 Studio 中写操作的成功与失败反馈，避免将 CLI 命令、退出码和 stdout 直接作为普通用户的主要结果提示。用户应能立即知道操作是否成功；操作失败时，不丢失弹窗、表单内容或可重试上下文。

## 方案

使用 `@mantine/notifications` 提供全局 toast，并复用现有 Mantine 主题。应用根节点挂载一个 `Notifications` 容器，业务组件通过统一封装显示成功或失败消息，避免各页面自行决定颜色、时长和错误格式。

统一反馈规则：

- 成功使用绿色 toast，默认约 3 秒自动关闭。
- 失败使用红色 toast，默认约 6 秒自动关闭。
- toast 标题说明操作结果，正文使用面向用户的简短信息。
- 后端返回 HTTP 成功但业务状态为 `failed`、`conflict` 或非零退出码时，仍按失败处理。
- 网络异常和不可解析响应统一转换为可读错误，不向用户展示堆栈。

## 弹窗与表单行为

- 创建、编辑和删除仅在业务确认成功后关闭弹窗。
- 失败时弹窗保持打开，已输入内容、选择项和当前对象不变。
- 弹窗内保留简短的持久错误信息，便于 toast 消失后继续查看和重试。
- 重新提交时清除旧的表单错误；新的失败替换旧错误。
- 成功后按现有逻辑刷新列表，并重置创建表单；编辑和删除不额外重置无关状态。

## 覆盖范围

### Agent、Workflow、Preset

- 创建、编辑、启用、停用和删除统一显示 toast。
- Agent、Workflow、Preset 页面不再展示原始 lifecycle 命令回显。
- Workflow 和 Preset 的文件读取错误、必填校验仍显示在表单内；这类错误不属于服务端写操作，不额外弹 toast。

### 设置与环境

- 高级设置保存、桌面端自动检查更新开关、CLI 安装或更新、Skill 安装或更新统一显示结果 toast。
- 设置失败时保留当前选择和输入；开关保存失败时恢复为服务端已确认值。
- CLI 与 Skill 的状态、版本和诊断信息继续显示在页面；一次性命令结果不再作为主要反馈长期占位。
- 应用更新的检查结果、下载进度和重启状态继续保留在更新卡片中，因为它们是持续状态，不替换为纯 toast。

### 运行与活动

- 活动删除成功或失败显示 toast；失败时删除确认弹窗保持打开并显示错误。
- Call 采纳、关闭 reviewer session、清理过期 session 显示结果 toast；失败时保留当前输入或页面状态。
- Run 安全动作显示结果 toast，但保留命令输出，因为该区域明确承担运行诊断和操作证据职责。

## 组件边界

- 全局通知层只负责展示和标准样式，不保存业务状态。
- 各业务组件负责决定何时关闭弹窗、保留表单和刷新数据。
- API/应用层负责将响应统一判定为成功或失败，避免组件把“请求已返回”误当成“操作成功”。
- 错误文案优先使用服务端提供的可读消息；缺失时按操作类型提供默认中文消息。

## 测试

- 单元测试覆盖成功、HTTP 失败、业务失败和异常四类结果判定。
- 组件测试覆盖成功关闭弹窗、失败保留弹窗和输入、toast 内容与类型。
- 源码/渲染测试确认 Agent、Workflow、Preset 的原始 lifecycle 命令块已移除。
- 回归测试确认应用更新进度、CLI/Skill 状态诊断和 Run 安全动作证据仍然可见。
- 运行 Studio 前端构建与相关 Node 测试，最后执行全量测试。

## 非目标

- 不改变后端 API、CLI 命令或持久化格式。
- 不把读取、加载和后台刷新错误全部改为 toast；需要长期可见的页面状态仍使用 Alert。
- 不为通知增加历史中心、撤销操作或自定义队列策略。
