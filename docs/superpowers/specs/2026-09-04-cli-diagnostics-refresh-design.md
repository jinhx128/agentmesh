# CLI 检测刷新设计

## 目标

在设置 / 环境的“命令行工具”和“CLI 检测”页签中增加“刷新”按钮，让用户无需重启桌面端或重新进入页面即可重新检测 AgentMesh CLI 与本机 Provider CLI。

## 交互

- “命令行工具”刷新按钮位于标题右侧、状态徽标左侧。
- “CLI 检测”刷新按钮位于标题右侧、检测数量徽标左侧。
- 按钮使用刷新图标和“刷新”文字，保持小尺寸、轻量样式。
- 两个按钮共用同一个刷新状态；刷新期间保留当前内容，同时让两个按钮进入加载和禁用状态，避免重复请求和页面闪烁。
- 命令行工具页发起刷新成功后提示“命令行工具状态已刷新”，CLI 检测页发起刷新成功后提示“CLI 检测已刷新”。
- 失败后保留当前列表，并按入口分别提示“命令行工具状态刷新失败”或“CLI 检测刷新失败”，同时用现有错误 toast 展示可读诊断。
- 刷新未结束时忽略重复点击。

## 数据流

复用现有 `GET /api/desktop/integrations` 接口，不增加后端 API。`App` 提供返回 `Promise<void>` 的刷新回调，在请求成功后替换完整的环境集成报告；请求失败时抛出规范化错误，由 `AgentIntegrationsPanel` 负责按钮状态和 toast。

虽然入口位于 CLI 检测页签，接口仍会返回并刷新命令行工具、Agent Skill 和 Provider CLI 三部分数据。这保证页面中的环境信息来自同一次检测快照，不产生局部数据版本不一致。

## 错误处理

刷新不把页面状态切换为全局 `loading` 或 `error`，因此失败时已有结果继续可见。首次加载仍沿用原有页面级加载与错误状态。

## 测试

- UI 契约测试验证两个刷新按钮分别位于命令行工具和 CLI 检测模块，并连接同一刷新回调。
- 组件交互测试验证刷新期间禁用、成功提示和失败提示。
- App 源码契约验证刷新请求不清空现有环境数据，且规范化并抛出错误。
- 运行 Studio UI 定向测试、前端构建和完整测试。

## 非目标

- 不新增单独的 CLI 检测接口。
- 不加入自动轮询。
- 不改变 CLI 探测规则、路径解析或版本检测逻辑。
