# 关于页版本与更新整合设计

## 背景

关于页当前用“版本与更新”和“应用更新”两张卡片分别展示发布版本与桌面端原生更新器，两处都有状态徽标和检查按钮。环境页又单独提供 AgentMesh“命令行工具”页签，展示 CLI 安装位置、版本及安装或更新操作。

这些能力的数据来源不同，但用户心智都属于 AgentMesh 自身的安装、版本和升级。当前布局既重复展示桌面端状态，也把 AgentMesh CLI 与 Codex、Claude、Cursor、Antigravity、OpenCode 等外部工具混在“环境”中。

## 目标

- 关于页只保留一个“版本与更新”卡片。
- 在同一张卡片内按“AgentMesh CLI”和“桌面应用”两个组件分区展示状态与操作。
- 只保留一个“重新检查”入口，同时刷新发布版本、AgentMesh CLI 和桌面端原生更新状态。
- 将 AgentMesh“命令行工具”从环境页迁入关于页。
- 环境页只保留 Agent Skill 和外部 Provider CLI 检测。
- 保留兼容性异常、更新失败、下载进度及安装失败的可读反馈。

## 信息架构

关于页继续保留现有外层容器和“关于”标题，内部只渲染一张 `settings-version-update` 子卡片，不再渲染独立的 `desktop-app-updater` 卡片。

卡片结构固定为：

1. 标题栏：左侧“版本与更新”，右侧依次为“重新检查”按钮和唯一的总体状态徽标。
2. 兼容性提示：仅在工作区为只读或拒绝访问时显示。
3. AgentMesh CLI 分区：展示已安装版本、最新版本和安装路径；右侧展示 CLI 状态与“安装”“更新”或“重新安装”操作。
4. 桌面应用分区：展示当前版本和最新版本；右侧展示桌面更新状态，在发现更新时显示“安装并重启”。下载进度、更新说明和错误显示在本分区内。
5. 桌面更新设置：在桌面应用分区底部展示“自动检测桌面端更新”开关和说明；浏览器 Studio 不具备原生能力时不渲染这一行。

两个组件分区使用同一卡片内的普通布局、分隔线和响应式网格，不使用嵌套 Card。桌面宽度下字段左右分布；窄屏下依次堆叠，操作按钮不覆盖路径或状态文字。

不再展示以下重复或低价值信息：

- 顶部独立的“当前版本 / 最新版本 / CLI 更新 / 桌面端更新”四宫格。
- 第二套“应用更新”标题、状态徽标和检查按钮。
- CLI 的原始 `source` 值；安装路径已经足以说明当前生效位置。
- CLI 更新命令和桌面下载 URL；用户通过界面按钮完成操作，失败时保留可读诊断。

## 环境页调整

环境页删除“命令行工具”页签及其内容，默认页签改为“Agent Skill”。原“CLI 检测”改名为“外部 CLI”，明确它只检测 Codex、Claude、Cursor、Antigravity 和 OpenCode 等 Provider 工具。

现有外部 CLI 检测规则、Agent Skill 安装能力和各自刷新行为保持不变。迁移的是 AgentMesh CLI 的展示与操作归属，不是后端探测逻辑。

## 数据来源

统一卡片组合三个现有数据源，不新增后端 API：

- `StudioIntegrationsReport.command_line_tool`：AgentMesh CLI 的安装状态、路径、已安装版本、最新版本和支持能力，是 CLI 分区的权威来源。
- `StudioUpdateReport`：最新发布版本、CLI/桌面端发布资产状态以及工作区兼容性关联信息。
- `DesktopAppUpdaterState`：桌面原生更新器的检查、下载、安装和重启状态；桌面 App 中是桌面更新操作的权威来源。

浏览器 Studio 没有原生 updater 时，桌面分区使用 `StudioUpdateReport.desktop` 展示发布状态，但不显示自动检查开关或“安装并重启”。

`SettingsAboutPanel` 接收 AgentMesh CLI 的独立状态与操作，不直接依赖整个环境面板。环境页仍可读取完整 `StudioIntegrationsReport`，但只消费 Skill 和 Provider CLI 部分。

## 统一刷新

标题栏“重新检查”由 `App` 提供一个统一异步回调，并行触发：

1. 服务端发布版本检查。
2. 环境集成检查，用于刷新 AgentMesh CLI 状态。
3. 桌面原生 updater 检查，仅在 Tauri Desktop 可用时触发。

刷新期间保留已有数据，按钮进入加载和禁用状态，不把整个关于页切换为空白 loading。各数据源独立落状态：一个检查失败不能清空另外两个已经成功的结果。

总体状态按以下优先级计算：下载或重启中、发现可更新、部分检查失败、检查中、已是最新。总体徽标只表达聚合结论，CLI 和桌面分区仍显示各自状态，避免一个组件失败时误导用户认为全部失败。

刷新全部成功时显示一次“更新状态已刷新” toast；部分失败时显示一次“部分更新状态检查失败”，具体原因留在对应分区。刷新不产生多条重复 toast。

## 安装与错误处理

- CLI 安装、更新和重新安装继续复用现有 `installCommandLineTool` 请求。操作成功后更新 CLI 分区并显示成功 toast；失败时保留卡片和现有数据，显示失败 toast。
- 桌面更新继续复用 Tauri updater 的下载、安装和重启流程。发现更新时才显示“安装并重启”。
- 自动检查偏好继续通过现有 Desktop preference API 保存。保存失败时恢复原值并在开关下方显示错误。
- 兼容性为 `read_only` 或 `refused` 时继续显示升级提示和已有诊断原因；正常兼容性不展示技术元数据。
- 页面首次加载的某个数据源失败时，只在对应分区显示错误；只有兼容性基础数据无法读取时才保留页面级错误。

## 测试

- UI 契约验证关于页只存在一张更新卡片，不再渲染独立“应用更新”卡片。
- 验证 AgentMesh CLI 和桌面应用两个分区的字段、状态、操作顺序及响应式结构。
- 验证环境页只保留 Agent Skill 和“外部 CLI”，且默认选中 Agent Skill。
- 验证统一刷新触发所有可用数据源、保留旧数据、防重复点击，并只产生一次汇总反馈。
- 验证 CLI 缺失、可更新、当前和错误状态，以及桌面 updater 不可用、检查中、当前、可更新、下载、重启和错误状态。
- 验证自动检查偏好保存成功与失败回滚。
- 运行 Studio UI 定向测试、完整测试、前端构建、Desktop packaging smoke 和 `git diff --check`。
- 在本地浏览器 Studio 与安装后的 `AgentMesh.app` 中验收布局、按钮和状态反馈。

## 非目标

- 不新增或修改后端更新、集成检测及安装 API。
- 不改变 CLI 安装路径选择、PATH 判断或 Provider CLI 探测规则。
- 不把 Agent Skill 或外部 Provider CLI 迁入关于页。
- 不增加自动轮询频率或后台下载更新。
- 不迁移或兼容历史 UI 状态。
