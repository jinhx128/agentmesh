# Studio 状态中文化设计

## 目标

Studio 的正常用户界面不再直接展示英文状态枚举。运行时数据、HTTP 接口和本地记录继续保存原始英文枚举，避免破坏兼容性、CLI 输出和历史数据。

## 范围

统一中文化以下用户可见状态：

- Call 执行状态、采纳状态、采纳历史和失败类型。
- 运行总览状态与错误占位页头。
- Reviewer Session 模式。
- 发布结论。
- Agent Skill 同步状态。
- 活动列表状态的悬浮提示和无障碍文案。
- Agent 生命周期非嵌入页头中的加载与错误状态。

已经使用中文标签的 Workflow 阶段、Agent 启停、CLI 更新和桌面端更新状态保持现状。

## 非目标

- 不修改运行时 schema、API 类型、本地记录或 CLI 的英文枚举。
- 不翻译 Agent、适配器、模型、文件名、命令、日志和诊断原文。
- 不借此改动清理所有英文产品名或技术术语。

## 展示规则

状态按业务域映射，避免同一个英文值在不同语境中含义冲突：

- Call：`running` 为“运行中”，`success` 为“成功”，`failed` 为“失败”，`aborted` 为“已中止”，`timeout` 为“已超时”，`stale` 为“已失联”。
- 采纳：`unreviewed` 为“未处理”，`accepted` 为“已采纳”，`rejected` 为“已拒绝”，`superseded` 为“已取代”。
- 运行：识别运行级状态和带阶段前缀的状态，使用既有阶段中文名组合中文状态。
- Reviewer Session：`interactive_continuous` 为“连续会话”，`independent` 为“独立会话”；已知的 fresh/resume 变体使用对应中文语义。
- 发布结论：`ready` 为“可发布”，`not_ready` 为“暂不可发布”，`needs_decision` 为“需要决策”，无效值为“无效结论”。
- Skill：`ok` 为“正常”，`missing` 为“未安装”，`unreadable` 为“无法读取”，`content_mismatch` 为“内容不一致”，`legacy_only` 为“仅有旧版配置”，`failed` 为“失败”。
- Call 失败类型使用中文短语，例如 `process_failed` 为“进程执行失败”、`spawn_failed` 为“启动失败”、`timeout` 为“调用超时”。

已知状态必须显示中文。遇到未来新增、当前版本不认识的状态时，普通界面显示“未知状态”，原始值只在日志或诊断证据中保留。

## 实现结构

在 Studio 前端增加集中但按业务域拆分的状态展示函数。组件只负责选择正确的业务域映射，不在 JSX 中继续直接输出状态枚举。已有语义正确的映射优先复用，重复映射收敛到同一处。

状态值仍用于 CSS class、请求参数和逻辑判断；只有渲染给用户的文本经过中文展示函数。

## 测试

- 先增加会失败的渲染测试，证明 Call 详情不再出现英文执行/采纳状态，并覆盖采纳历史。
- 覆盖运行总览、Reviewer Session、发布结论和 Skill 同步状态的中文输出。
- 覆盖未知状态回退为“未知状态”，同时确认底层对象仍保留原始枚举。
- 运行 Studio UI 定向测试、TypeScript 类型检查及项目现有相关测试。

## 验收标准

- 截图中的 `success` 和 `superseded` 均显示中文。
- 上述范围内的已知状态不再以英文枚举出现在普通界面。
- 状态颜色、操作行为、接口请求和历史数据格式不变。
- 日志、命令和诊断原文不被翻译或改写。
