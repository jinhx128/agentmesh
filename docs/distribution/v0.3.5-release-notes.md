# AgentMesh v0.3.5

修复通过 AgentMesh 调用 Claude CLI 时，宿主认证环境覆盖本机第三方 API 配置，导致终端可用但独立 agent 提示未登录或网关认证失败的问题。

## 修复

- 独立子进程不再继承父 Claude 会话的嵌套标记、宿主管理 provider 标记和宿主认证变量引用。
- Claude adapter 在宿主管理 provider 且未继承独立 API 凭据时，清除继承的网关地址，使 CLI 可读取自身 provider 设置。
- 保留继承的 API 凭据和模型配置；Codex、Cursor、OpenCode、Antigravity 与 command adapter 保留其 `ANTHROPIC_*` 配置；显式 agent 环境配置优先。
- Windows 按不区分大小写的规则识别环境变量，显式配置替换继承的同名大小写变体。
- 同步、异步调用，doctor、模型发现和全局 CLI 版本探测使用一致的环境构造规则，并补充真实子进程回归测试。

## 兼容与升级

- 数据格式、Packet schema 和命令行接口不变，无需迁移已有数据。
- 使用凭据 helper 的自定义 Claude endpoint 若与宿主管理标记共存、且环境中没有 API 凭据，需要通过 agent 的显式 `env` 保留 `ANTHROPIC_BASE_URL`。
- CLI 与 Desktop 是独立安装渠道。桌面端使用同版本完整 DMG 替换 `AgentMesh.app` 或应用内更新，不能混用旧 sidecar、runtime 或 UI 资源。CLI 使用本版本 npm 包或 tarball 单独更新。
- `0.1.10` 用户需要先手动替换一次完整 DMG；`0.1.11` 及之后版本支持应用内更新。
- 资产包含 npm tarball、macOS Apple Silicon DMG、带 Tauri 更新签名的应用归档与签名文件、`latest.json`、Skill markdown 和 `SHA256SUMS`。
- DMG 未使用 Developer ID 签名、未 notarize，首次打开可能需要在 Finder 中右键选择「打开」。
